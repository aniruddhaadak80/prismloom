ADR-0001: Monorepo layout under apps/web only
Status: accepted
Date: 2026-10-15
Decision: Keep PRISMLOOM as a single Next.js app under src/app with lib/ and components/ rather than a Turborepo monorepo.
Rationale: The concept is a browser-first creative playground; server complexity is minimal. A monorepo adds indirection without benefit at this scope. Polyglot services live in services/ and deploy separately if desired.
Consequences: Simpler CI, single build, easier local dev. Future mobile (Expo) would move to apps/web + apps/mobile.

ADR-0002: Zero-key local AI by default
Status: accepted
Date: 2026-10-15
Decision: All "intelligence" (scene suggestion, prompt tags) is deterministic local code (Python agent_service + TS heuristics). No LLM API keys are required or bundled.
Rationale: The amazing-repo contract requires zero-keys runnable demos. Users can optionally wire real models later via env.
Consequences: Predictable offline behavior; no secret management for the demo; quality is heuristic not generative.

ADR-0003: Tailwind v4 + Geist design system
Status: accepted
Date: 2026-10-15
Decision: Use Tailwind v4 with a custom neon dark palette and Geist Sans/Mono.
Rationale: Matches Next.js 16 defaults and gives a high-contrast creative-coding aesthetic.
Consequences: Custom CSS variables; dark-first theme.

ADR-0004: Raw Three.js instead of @react-three/fiber
Status: accepted
Date: 2026-10-15
Decision: WebGL scenes are built with plain three.js inside next/dynamic client components.
Rationale: Avoids R3F abstraction overhead for simple parametric scenes; easier to reason about frame loop and disposal.
Consequences: Manual scene lifecycle/dispose; more boilerplate per scene but full control.

---
ADR-0005: Procedural Web Audio, no samples
Status: accepted
Date: 2026-10-15
Decision: Audio tracks are synthesized oscillators (square/saw/triangle/sine) with step sequencers; no audio assets.
Rationale: Zero-key, zero-bandwidth, fully in-browser. Fits creative-coding vibe.
Consequences: Limited timbral richness vs samples; no licensing concerns.

---
ADR-0006: Prompts pre-generated, not live LLM calls
Status: accepted
Date: 2026-10-15
Decision: The 5,200+ prompt library is a static JSON file generated by scripts/gen-prompts.mjs at build time.
Rationale: Instant search, works offline, deterministic, no API cost.
Consequences: Library is fixed until regenerated; not personalized per user.

---
ADR-0007: Gamification state in localStorage
Status: accepted
Date: 2026-10-15
Decision: XP, level, stars, badges persist in browser localStorage only.
Rationale: No backend/auth needed for the demo; instant load; privacy by default.
Consequences: Data is device-specific; clearing site data resets progress.

ADR-0008: Static export on Vercel
Status: accepted
Date: 2026-10-15
Decision: Deploy as Next.js static prerendered pages to Vercel production.
Rationale: All content is static; fastest edge delivery; cheapest hosting.
Consequences: Dynamic routes (profile/[id]) are prerendered shells; client fills data.
